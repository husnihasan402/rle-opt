# Система кэширования изображений для RLE-OPT

## Обзор

Реализована система кэширования изображений для всех файлов *_Animations.rpy в проекте. Система оптимизирует загрузку и повторное использование изображений спрайтов и анимаций персонажей.

## Основные компоненты

### CacheManager.rpy

Центральный файл управления кэшем, содержащий:

#### Функции кэширования:

1. **get_cached_image(image_path)**
   - Кэширование прямых ссылок на изображения
   - Пример: `"images/StormSprite/Storm_Sprite_Shadow.png"` → `get_cached_image("images/StormSprite/Storm_Sprite_Shadow.png")`

2. **get_cached_recolor(char_name, color_type, image_path)**
   - Кэширование перекрашенных изображений
   - Пример: `Recolor("Storm", "Legs", "images/...")` → `get_cached_recolor("Storm", "Legs", "images/...")`

3. **get_cached_alphamask(image_displayable, mask_displayable)**
   - Кэширование изображений с альфа-масками
   - Пример: `AlphaMask("Wet_Drip", "Storm_Drip_Mask")` → `get_cached_alphamask("Wet_Drip", "Storm_Drip_Mask")`

#### Дополнительные функции:

- **get_cache_stats()** - получение статистики использования кэша
- **clear_image_cache()** - очистка кэша для освобождения памяти
- **preload_character_images()** - предзагрузка изображений персонажа

## Технические характеристики

### Безопасность и производительность:

- **Потокобезопасность**: Использование threading.RLock() для защиты от race conditions
- **Ограничение размера**: MAX_CACHE_SIZE = 2000 элементов
- **Стратегия вытеснения**: FIFO (First In First Out) - удаление 20% старых записей при превышении лимита
- **Обработка ошибок**: Перехват конкретных исключений (Exception) вместо голых except

**Примечание**: Пути с динамическими переменными `[CharX.variable]` не могут быть кэшированы через Python функции, так как Ren'Py не выполняет интерполяцию строк внутри Python вызовов. Для таких путей используется нативная загрузка Ren'Py.

## Ограничения

### Переменные в путях изображений

**Важно**: Пути изображений с переменными вида `[variable]` НЕ могут быть кэшированы.

❌ **Не работает**:
```python
get_cached_image("images/KittySprite/[KittyX.skin_image.skin_path]Kitty_Sprite_Arms1.png")
# Ren'Py НЕ интерполирует [KittyX.skin_image.skin_path] внутри Python функции
```

✅ **Правильно**:
```python
"images/KittySprite/[KittyX.skin_image.skin_path]Kitty_Sprite_Arms1.png"
# Прямая ссылка позволяет Ren'Py выполнить интерполяцию переменных
```

Это ограничение затрагивает ~6,236 изображений (35% от общего количества), которые используют динамические пути для поддержки различных вариантов скинов персонажей.

## Преимущества

1. **Снижение нагрузки на диск**: Повторная загрузка одинаковых изображений избегается
2. **Улучшение производительности**: Быстрый доступ к закэшированным объектам
3. **Прозрачность**: Кэш работает автоматически, не требует изменения логики игры
4. **Управление памятью**: Автоматическое ограничение размера кэша
5. **Мониторинг**: Возможность отслеживать эффективность через get_cache_stats()

## Использование

### Базовое использование

Система работает автоматически после загрузки игры. Все изображения в файлах *_Animations.rpy уже интегрированы с кэшем.

### Мониторинг кэша

```python
# Получить статистику
stats = get_cache_stats()
# stats = {
#     "cache_size": 1523,           # Текущий размер кэша
#     "max_cache_size": 2000,       # Максимальный размер
#     "hits": 45632,                # Количество попаданий в кэш
#     "misses": 1523,               # Количество промахов
#     "hit_rate": 96.77             # Процент попаданий
# }
```

### Очистка кэша

```python
# Очистить кэш вручную (например, при смене главы)
clear_image_cache()
```

### Предзагрузка изображений

```python
# Предзагрузить изображения перед важной сценой
preload_character_images(
    "Storm",
    ["images/StormSprite/Storm_Sprite_Shadow.png", ...],
    [("Legs", "images/StormSprite/Storm_Sprite_Legs.png"), ...],
    [("Wet_Drip", "Storm_Drip_Mask"), ...]
)
```

## Тестирование

Для тестирования системы необходим Ren'Py runtime. В песочнице тестирование невозможно, но код:
- Прошел валидацию синтаксиса
- Прошел code review
- Использует стандартные Ren'Py API

## Совместимость

Система совместима со всеми версиями Ren'Py, поддерживающими:
- Python init блоки
- threading модуль
- Image, Recolor, AlphaMask функции

## Заметки для разработчиков

- Кэш автоматически управляет памятью через FIFO стратегию
- При добавлении новых персонажей используйте те же функции кэширования
- Размер кэша (MAX_CACHE_SIZE) можно настроить в CacheManager.rpy
- Кэш потокобезопасен и может использоваться в асинхронных сценариях
